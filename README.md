# Tavonza AI Restaurant Platform - Standalone Backend

Production-grade, enterprise multi-tenant B2B SaaS backend for restaurant and bar operations, QR-based digital ordering, and intelligent kitchen/staff workflow management.

---

## 1. System Architecture

The backend is built as a **Clean Modular Monolith** in **NestJS 10 + Drizzle ORM + PostgreSQL + Redis + BullMQ**. It compiles into two distinct operational runtime processes from a single codebase:

```text
                               ┌─────────────────────────────────┐
                               │   Tavonza Backend Codebase      │
                               │             (src/)              │
                               └────────────────┬────────────────┘
                                                │
                       ┌────────────────────────┴────────────────────────┐
                       ▼                                                 ▼
        ┌───────────────────────────────┐               ┌─────────────────────────────────┐
        │  Web API & Realtime Gateway   │               │   Headless Background Worker    │
        │       (src/main.ts)           │               │       (src/worker.ts)           │
        ├───────────────────────────────┤               ├─────────────────────────────────┤
        │ • REST API & Swagger (v1)     │               │ • Outbox Event Processor        │
        │ • Socket.IO Realtime Gateway  │               │ • BullMQ Notification Worker    │
        │ • Customer/Staff Auth & RBAC  │               │ • BullMQ Email Dispatcher (SES) │
        │ • Stripe Webhooks & Billing   │               │ • Idle Table Session Cleanup    │
        └───────────────────────────────┘               └─────────────────────────────────┘
```

### Sister Repositories
The platform is organized into three decoupled repositories for clear team ownership:
- **`tavonza-backend`** (This Repository): Core REST API, WebSockets, RBAC, Business Domains, Database Schema, and Workers.
- **`tavonza-frontend`**: Next.js 14 applications (Customer PWA, Admin Dashboard, Waiter, Kitchen KDS, Cashier, Branch Manager).
- **`tavonza-ai`**: Python 3.11 FastAPI service for AI Agents and conversational ordering, calling the backend strictly via the Tool Gateway.

## 3. Quick Start & Developer Workflow

### Prerequisites
- Node.js >= 20.0.0
- pnpm >= 9.0.0
- Docker & Docker Compose

### 1. Installation
```bash
pnpm install
```

### 2. Environment Configuration
```bash
cp .env.example .env
```

### 3. Local Infrastructure (PostgreSQL & Redis)
```bash
pnpm docker:up
```

### 4. Database Setup & Migrations
```bash
# Push schema or run migrations
pnpm db:push
# Or verify schema consistency
pnpm drizzle-kit check

# Seed initial test data
pnpm db:seed

# Launch visual Drizzle Studio
pnpm db:studio
```

### 5. Running in Development
```bash
# Run Web API (Port 3000)
pnpm start:dev

# Run Background Queue & Outbox Worker in a separate terminal
pnpm start:worker:dev
```

### 6. Automated Testing & Verification
```bash
# Run domain and unit tests
pnpm test

# Run TypeScript compiler checks
pnpm typecheck

# Build dual-target production bundles
pnpm build
```

## 4. API Documentation & Frontend Contracts

- **Swagger UI**: Accessible at `http://localhost:3000/docs` when the API is running.
- **OpenAPI Schema (JSON)**: `http://localhost:3000/docs-json`.
- **Frontend Code Generation**: Frontend repositories generate strictly-typed TypeScript clients directly from the OpenAPI spec:
  ```bash
  npx openapi-typescript http://localhost:3000/docs-json -o packages/contracts/src/schema.d.ts
  ```

## 5. Deployment Architecture

Container images are built from the unified multi-stage [`docker/Dockerfile`](docker/Dockerfile):

```bash
# Build Web API container image
docker build --target api -t tavonza-api:latest -f docker/Dockerfile .

# Build Worker container image
docker build --target worker -t tavonza-worker:latest -f docker/Dockerfile .
```
